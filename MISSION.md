# Mission: Read and design trustworthy AI customer service systems

## Why
Learn the architectural ideas in hyperMoss/anker-OntoCare and hyperMoss/anker-haike, especially ontology and deterministic business decisions, in order to independently design an AI customer support platform.

## Success looks like
- Explain ontology, knowledge retrieval, state machines, and action gates without conflating them.
- Trace an ambiguous customer request through the real code in both projects.
- Draft a small domain model and guarded service workflow suitable for a new customer-service MVP.

## Constraints
- Use primary sources and linked source files; distinguish implemented behavior from proposals.
- Prefer short Chinese interactive lessons, one concept and a verifiable exercise per lesson.
- Do not modify either reference GitHub repository.

## Out of scope
- Launching a production customer-service system in the first lesson.
- Deploying RDF/OWL or a graph database before requirements justify it.
