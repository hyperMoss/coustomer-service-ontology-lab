OntoCare allowed_actions() 分支

条件关键允许动作禁止 / 注意
product 缺失ask_product、search_knowledge不允许 propose_replacement 或 direct_refund
产品已知，warranty UNKNOWN / PENDING_RECHECKask_country、ask_seller、request_proof不能 tell_expired；未知不等于过保
warranty EXPIREDpropose_paid_repair不能建议直接换货或退款
warranty VALID，ts FAILED，dealer AUTHORIZEDprepare_replacement_review仅准备审核材料，不是已经换货
warranty VALID，within_30d，dealer AUTHORIZEDprepare_return_review必须人工核查退货资格；不是直接退款
warranty VALID，dealer NOT_AUTHORIZEDguide_contact_seller不能将未授权渠道当作官方质保

源码细节：USER_REPORTED_FAILED 不等于 FAILED。前者是客户反馈，后者才满足 prepare_replacement_review 的这一项源码条件。此外，规则中 direct_refund 始终被禁止，项目未接真实退款执行器。

与 haike 的连接

候选动作空间：产品 / 保修 / 渠道 / 排障状态 → Allowed / Forbidden。

授权闸门：eligibility + evidence + safety + idempotency + review → 允许提交服务单或人工处理。

这两层是设计思想上的联系，并非两个仓库已经互相调用。haike 提交的是赛题服务单，提交后仍有人工接续，不等同真实退款履约。

可复用的设计原则

  1. 先定义产品 PN、订单商品行、知识来源和证据版本，再考虑向量检索。
  2. 不要将未知状态强行变成真或假；未知应该触发澄清或人工核查。
  3. 将客户陈述与已核实事实分开，把“想退货”与“已批准退款”分开。
  4. 从已知状态计算候选动作，敏感写入再经过独立授权与幂等校验。
