从事实到执行
6 个关键对象

遇到设计难题时，先判断它属于哪个层级，不要一开始就增加一个 Agent。

对象或机制职责容易犯的错误
业务本体 / Ontology定义 Product、Order、Issue、Evidence 等语义、关系和约束把数据表或向量库误认成完整本体
Fact（事实）带原话、主体、极性、时间和来源的具体事实把「没有冒烟」当作正在冒烟；用摘要覆盖原话
Issue（问题）关联一组事实、待答卡片、诊断步骤和处理状态一段聊天所有诉求只允许有一个状态
SessionState一轮图的共享状态，包含活跃 Issue、执行信息及待答项把前端断线当作事实或业务状态丢失
AuthorizationGate执行前五项检查全部通过才放行LLM 输出「可以退款」就直接调用退款 API
Idempotency key重复调用同一请求识别为同一动作，先核查再重试接口超时后盲目再次创建服务单

五项授权检查

名称一行定义
eligibility质保或物流资格满足。
evidence必要材料齐全，客户已确认。
safety没有阻止操作的安全限制。
idempotency案件与执行状态允许本次尝试。
review候选方案与独立核对结果一致，或走源码明确的人工/模型关闭分支。

典型设计原则

领域模型定义世界；事实账本记录世界的证据；状态机推进工作；规则闸门检查权限；执行器负责有副作用的动作；可观测与评测解释为什么这样做。
