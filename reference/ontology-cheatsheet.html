Reference 01

客服业务本体
概念速查表

从抽象术语回到一个你能直接编码的领域模型。

核心公式

领域概念（类） + 具体对象（实例） + 可验证的关系 + 适用性约束

实例：S1 Pro 是商品名称；T2080 和 T8D04 是不同产品；知识条目只对它所关联的型号有效。

最小词汇

术语含义客服例子
Class 类某类事物的定义Product、Order、Knowledge
Individual 实例一个具体对象产品 PN=T2080
Property 属性对象的具体字段category=robot_vacuum
Relation 关系对象之间的联系Knowledge → appliesTo → Product
Constraint 约束哪些结论 / 动作可被允许型号未确认不得给专属步骤
Evidence 证据结论的可追溯来源订单字段、官方 FAQ 行

容易混淆的三件事

本体 ≠ 向量数据库

向量数据库擅长相似度检索，本体强调语义对象、关系和约束。

本体 ≠ 知识图谱

本体描述知识的概念和语义规则；知识图谱通常承载大量实体与关系实例。两者可以组合。

本体 ≠ 业务流程引擎

本体定义世界和关系；流程引擎管理状态、时序及执行步骤。实际系统可以由确定性规则将两者连接。

用了 Ontology 不等于用了 OWL

OntoCare 的双本体使用 Python/JSON 规则，不是 RDF/SPARQL 推理系统。

如何在新客服系统中落地

先定义最少的实体：Customer、Conversation、Issue、Product、Order、Knowledge、Evidence、Action。再定义哪些关系必须被验证，以及哪些动作不能由 AI 自行执行。

先用 TypeScript 类型、PostgreSQL 外键与规则函数验证，等确实需要跨领域语义推理时，再考虑 RDF/OWL 或专用图数据库。
